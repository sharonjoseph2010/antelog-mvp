# Antelog MVP - Engineer Onboarding Guide

## Overview

**Antelog** is a trust-powered social recommendation platform that enables verified users to create, share, and discover authentic recommendations within their social network. The application emphasizes privacy, authenticity, and ad-free content sharing through a verified community model.

## Quick Start

### Development Setup
```bash
# Install dependencies
npm install

# Start development server
npm run dev

# Build for production
npm run build

# Lint code
npm run lint
```

### Technology Stack
- **Frontend**: React 18 + TypeScript + Vite
- **UI Framework**: Radix UI + shadcn/ui + Tailwind CSS
- **Backend**: Supabase (PostgreSQL + Auth + Realtime)
- **State Management**: TanStack Query
- **Routing**: React Router v6
- **Themes**: next-themes for dark/light mode

## Understanding the Codebase

> **Important**: This entire codebase was generated by LLMs, not written by humans. As such, patterns may be inconsistent and code structure might not follow traditional human conventions.

### Key Characteristics of LLM-Generated Code:
- **Verbose implementations** - LLMs tend to be explicit rather than concise
- **Mixed patterns** - Different sections may use different architectural approaches
- **Over-commenting** - Excessive documentation in some areas
- **Functional over elegant** - Code prioritizes working over optimal structure
- **Rapid iteration artifacts** - Evidence of quick feature additions without refactoring

### Code Navigation Tips:
1. **Start with types** - `src/integrations/supabase/types.ts` defines the entire data model
2. **Follow the routes** - `src/App.tsx` shows all available pages and auth flow
3. **Check migration history** - `supabase/migrations/` reveals feature development timeline
4. **UI components are atomic** - Each component in `src/components/ui/` is self-contained

### Backend Architecture (Supabase)

#### Database Schema
The database follows a normalized structure with strong referential integrity:

```sql
-- Core entities
profiles (user data)
├── lists (user content)
│   └── list_items (list entries)
├── friendships (social connections)
├── groups (user-created groups)
└── requests (recommendation requests)
    └── request_responses (recommendation responses)

-- Discovery system
directory_entries (public searchable content)
├── directory_votes (quality voting)
└── search_analytics (usage tracking)

-- Growth mechanics
contact_imports (viral contact matching)
└── friend_suggestions (AI-powered suggestions)
```

#### Security Model
- **Row Level Security (RLS)** enabled on all tables
- **Authentication-first** - All access requires `auth.uid()`
- **Relationship-based access** - Content visibility based on friendships
- **Role-based admin controls** - Admin/moderator/user hierarchy

#### Key Database Functions
```sql
-- Core business logic
normalize_profile_handle()     -- Handle standardization
create_mutual_friend_suggestions() -- Viral growth engine
sync_directory_entries()       -- Content discovery sync
get_extended_network()         -- Friends-of-friends discovery
has_role()                     -- Permission checking
```

### Data Flow Patterns

#### Content Creation Flow
```
User creates list → Auto-sync to directory (if public) → Search indexing → Discovery
```

#### Social Connection Flow
```
Contact import → Contact matching → Friend suggestions → Friend requests → Friendships
```

#### Recommendation Flow
```
User creates request → Network notification → Responses → Voting → Quality ranking
```

## Development Guidelines

### Working with LLM-Generated Code

#### Best Practices:
1. **Understand before modifying** - LLM code can have unexpected dependencies
2. **Test thoroughly** - Generated code may have edge cases
3. **Follow existing patterns** - Don't introduce new patterns unnecessarily
4. **Document your changes** - Help future developers understand modifications
5. **Use TypeScript strictly** - Types are your friend in generated code

#### Common Pitfalls:
- **Over-engineered solutions** - LLMs sometimes create complex solutions for simple problems
- **Inconsistent naming** - Variable and function names may not follow consistent conventions
- **Buried business logic** - Important logic might be in unexpected places
- **Copy-paste artifacts** - Similar components may have subtle differences

### Code Modification Strategy

#### For Small Changes:
1. Identify the specific component/function
2. Understand its inputs/outputs and dependencies
3. Make minimal, surgical changes
4. Test the specific feature thoroughly

#### For Feature Additions:
1. Study similar existing features first
2. Follow the established patterns in that area
3. Use existing components and utilities
4. Maintain consistency with the current architecture

#### For Bug Fixes:
1. Reproduce the issue first
2. Check if it's a logic error or a data/state issue
3. Look for similar patterns elsewhere in the codebase
4. Fix the root cause, not just the symptom

## Common Development Tasks

### Adding a New Page
1. Create component in `src/pages/`
2. Add route in `src/App.tsx` with appropriate guards
3. Update navigation in Header component
4. Add any new database queries/mutations

### Adding Database Fields
1. Create migration in `supabase/migrations/`
2. Update TypeScript types in `src/integrations/supabase/types.ts`
3. Update relevant RLS policies
4. Update frontend components using the data

### Adding New Components
1. Study similar components for patterns
2. Use existing shadcn/ui components as base
3. Follow the atomic design principle
4. Ensure proper TypeScript typing

### Debugging Issues
1. Check browser console for frontend errors
2. Check Supabase dashboard for database errors
3. Use React Developer Tools for component state
4. Check network tab for API request/response issues

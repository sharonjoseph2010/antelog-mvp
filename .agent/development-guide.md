# Development Guide

## Getting Started

### Prerequisites
- Node.js 18+ and npm
- Git for version control
- Code editor (VS Code recommended)
- Basic understanding of React, TypeScript, and SQL

### Development Environment Setup

#### 1. Clone and Install
```bash
# Clone the repository
git clone <repository-url>
cd antelog-mvp

# Install dependencies
npm install

# Start development server
npm run dev
```

#### 2. Environment Configuration
Create `.env.local` file:
```bash
VITE_SUPABASE_URL=your_supabase_project_url
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
```

#### 3. Database Setup (if using local Supabase)
```bash
# Install Supabase CLI
npm install -g supabase

# Login to Supabase
supabase login

# Link to your project
supabase link --project-ref your-project-ref

# Pull database schema
supabase db pull

# Start local development
supabase start
```

## Development Workflow

### Working with LLM-Generated Code

#### Understanding Code Patterns
Since this codebase was generated by LLMs, keep these characteristics in mind:

1. **Verbose Implementation**: Code tends to be explicit rather than concise
2. **Functional Over Elegant**: Working solutions prioritized over optimal architecture
3. **Mixed Patterns**: Different sections may use different approaches
4. **Rapid Iteration Artifacts**: Evidence of quick feature additions without refactoring

#### Best Practices for LLM Code:
```typescript
// ✅ Follow existing patterns
// If you see this pattern in multiple places:
const { data, error } = await supabase
  .from('table_name')
  .select('*')
  .eq('user_id', user.id);

// Use the same pattern for new features:
const { data, error } = await supabase
  .from('new_table')
  .select('*')
  .eq('user_id', user.id);

// ❌ Don't introduce new patterns without good reason
// Avoid changing established patterns unless necessary
```

### Code Modification Strategy

#### For Small Changes (Bug Fixes, UI Tweaks)
1. **Identify the specific component**:
   ```bash
   # Find component responsible for feature
   grep -r "specific error message" src/
   # or
   grep -r "Button text" src/components/
   ```

2. **Understand dependencies**:
   ```typescript
   // Check imports to understand dependencies
   import { useQuery } from '@tanstack/react-query';
   import { supabase } from '@/integrations/supabase/client';
   // These indicate data fetching patterns used
   ```

3. **Make surgical changes**:
   ```typescript
   // Before (example bug fix)
   const { data } = await supabase
     .from('lists')
     .select('*')
     .eq('owner_id', user.id); // Bug: user might be null

   // After (defensive fix)
   if (!user?.id) throw new Error('User not authenticated');
   const { data } = await supabase
     .from('lists')
     .select('*')
     .eq('owner_id', user.id);
   ```

#### For Feature Additions
1. **Study similar existing features**:
   ```typescript
   // If adding a new list type, study existing Lists.tsx
   // If adding notifications, study NotificationCenter.tsx
   // Copy the established patterns
   ```

2. **Follow the component structure**:
   ```typescript
   const NewFeatureComponent = () => {
     // 1. Auth and user state
     const user = useUser();
     
     // 2. Data fetching
     const { data, isLoading } = useQuery({
       queryKey: ['new-feature', user?.id],
       queryFn: fetchNewFeatureData
     });
     
     // 3. Mutations
     const createMutation = useMutation({
       mutationFn: createNewFeature,
       onSuccess: () => {
         queryClient.invalidateQueries(['new-feature']);
       }
     });
     
     // 4. Event handlers
     const handleCreate = (formData) => {
       createMutation.mutate(formData);
     };
     
     // 5. Render with loading/error states
     if (isLoading) return <LoadingSpinner />;
     
     return (
       <div className="container mx-auto px-4 py-8">
         {/* Component content */}
       </div>
     );
   };
   ```

3. **Add database migrations if needed**:
   ```sql
   -- Create new migration file
   -- supabase/migrations/YYYYMMDDHHMMSS_feature_name.sql
   
   CREATE TABLE new_feature_table (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     user_id UUID NOT NULL REFERENCES profiles(id) ON DELETE CASCADE,
     content TEXT NOT NULL,
     created_at TIMESTAMPTZ DEFAULT now()
   );
   
   -- Add RLS policies
   ALTER TABLE new_feature_table ENABLE ROW LEVEL SECURITY;
   
   CREATE POLICY "Users can view own data" ON new_feature_table
     FOR SELECT USING (auth.uid() = user_id);
   ```

### Database Development

#### Working with Migrations
```bash

supabase migration new feature_name

# Apply migrations locally
supabase db reset

# Push to remote
supabase db push
```

#### RLS Policy Patterns
```sql
-- Self-ownership pattern (most common)
CREATE POLICY "self_access" ON table_name
  FOR ALL USING (auth.uid() = user_id);

-- Friendship-based access
CREATE POLICY "friends_access" ON lists
  FOR SELECT USING (
    visibility = 'public' 
    OR owner_id = auth.uid()
    OR (visibility = 'friends' AND owner_id IN (
      SELECT friend_id FROM user_friends WHERE user_id = auth.uid()
    ))
  );

-- Role-based access
CREATE POLICY "admin_access" ON table_name
  FOR ALL USING (
    auth.uid() = user_id 
    OR has_role(auth.uid(), 'admin')
  );
```

### Frontend Development

#### Component Development Workflow
```typescript
// 1. Create component file
// src/components/features/NewFeature.tsx

import React from 'react';
import { useQuery, useMutation } from '@tanstack/react-query';
import { Button } from '@/components/ui/button';
import { Card, CardContent, CardHeader, CardTitle } from '@/components/ui/card';
import { supabase } from '@/integrations/supabase/client';

// 2. Define types (use existing patterns)
interface NewFeatureProps {
  userId: string;
}

interface NewFeatureData {
  id: string;
  title: string;
  content: string;
  created_at: string;
}

// 3. Implement component following established patterns
export const NewFeature: React.FC<NewFeatureProps> = ({ userId }) => {
  // Data fetching
  const { data, isLoading, error } = useQuery({
    queryKey: ['new-feature', userId],
    queryFn: async () => {
      const { data, error } = await supabase
        .from('new_feature_table')
        .select('*')
        .eq('user_id', userId)
        .order('created_at', { ascending: false });
      
      if (error) throw error;
      return data as NewFeatureData[];
    },
    enabled: !!userId
  });

  // Mutations
  const createMutation = useMutation({
    mutationFn: async (newData: Omit<NewFeatureData, 'id' | 'created_at'>) => {
      const { error } = await supabase
        .from('new_feature_table')
        .insert([{ ...newData, user_id: userId }]);
      
      if (error) throw error;
    },
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['new-feature', userId] });
    }
  });

  // Loading and error states
  if (isLoading) return <div>Loading...</div>;
  if (error) return <div>Error: {error.message}</div>;

  return (
    <Card>
      <CardHeader>
        <CardTitle>New Feature</CardTitle>
      </CardHeader>
      <CardContent>
        <div className="space-y-4">
          {data?.map((item) => (
            <div key={item.id} className="p-4 border rounded">
              <h3 className="font-medium">{item.title}</h3>
              <p className="text-sm text-muted-foreground">{item.content}</p>
            </div>
          ))}
          <Button onClick={() => createMutation.mutate({ 
            title: 'New Item', 
            content: 'Content' 
          })}>
            Add New
          </Button>
        </div>
      </CardContent>
    </Card>
  );
};
```

### Performance Optimization

#### Frontend Optimization
```typescript
// Optimize expensive components with React.memo
export const ExpensiveComponent = React.memo(({ data }) => {
  // Component logic
}, (prevProps, nextProps) => {
  // Custom comparison function
  return prevProps.data.id === nextProps.data.id;
});

// Optimize query keys for better caching
const useOptimizedQuery = (userId: string, filters: Filters) => {
  return useQuery({
    queryKey: ['data', userId, filters], // Include all dependencies
    queryFn: fetchData,
    staleTime: 5 * 60 * 1000, // 5 minutes
    cacheTime: 10 * 60 * 1000, // 10 minutes
  });
};

// Implement optimistic updates
const useOptimisticMutation = () => {
  const queryClient = useQueryClient();
  
  return useMutation({
    mutationFn: updateData,
    onMutate: async (newData) => {
      // Cancel ongoing queries
      await queryClient.cancelQueries(['data']);
      
      // Get previous data
      const previousData = queryClient.getQueryData(['data']);
      
      // Optimistically update
      queryClient.setQueryData(['data'], old => [...old, newData]);
      
      return { previousData };
    },
    onError: (err, newData, context) => {
      // Rollback on error
      queryClient.setQueryData(['data'], context.previousData);
    },
    onSettled: () => {
      // Refetch after mutation
      queryClient.invalidateQueries(['data']);
    },
  });
};
```
